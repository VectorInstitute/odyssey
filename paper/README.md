# Manuscript: npj Digital Medicine

Everything for the paper lives here and only here; results, figures and text
are regenerated from the code and the experiment registry (`docs/experiments.md`),
never from memory.

## Files

| File | What |
|---|---|
| `main.tex` | The manuscript (currently an outline: every section carries a comment saying what it must establish, `[TBD]` marks anything not final) |
| `references.bib` | Nature-style numbered references (limit 60) |
| `figures/` | Figure files (PDF/EPS), one file per figure, generated by scripts (to come) |
| `sn-jnl.cls`, `sn-nature.bst` | Springer Nature LaTeX template v3.1 (Dec 2024) and the reference style it names for Nature Portfolio journals |
| `template-sn-article.tex`, `template-user-manual.pdf` | The untouched template sample and manual, for reference |
| `Makefile` | `make` builds `main.pdf` with latexmk |

## Journal rules the outline follows

From the journal's content-types and submission-guidelines pages (read 2026-08-17):

- Article: title of at most 15 words, free of punctuation, idioms and puns.
- Abstract of at most 150 words, no subheadings.
- Introduction: no subheadings. Results: subheadings required. Discussion: no
  subheadings, and no "Limitations" or "Conclusions" sections. Methods:
  subheadings required, ethics and consent details for human data, all
  methods in the main file (not Supplementary Information).
- After Methods, in this order: Data availability (mandatory), Code
  availability, Acknowledgements (funding declared here; no separate Funding
  section), Author contributions (initials, every author), Competing
  interests (mandatory even if none), References (about 60, Nature style,
  numbered by first appearance), figure legends (at most 350 words each;
  multi-panel figures on one page, panels a), b), c)).
- Initial submission is a single PDF with figures placed in the text or at
  the end; LaTeX source is only needed at acceptance. Supplementary
  Information is one separate PDF. The Nature Portfolio Reporting Summary
  and Editorial Policy Checklist are requested at revision.
- No strict word limits are imposed, but concise writing is expected.

## Working rules

- No patient-level data or identifiers in this directory, ever (traces in
  figures must be aggregate-safe or synthetic).
- Numbers in the text come from `docs/experiments.md` and the report JSONs;
  cite the run name and commit next to each figure script.
- No em dashes in prose (project style).
- Build before committing: `make` must succeed; `main.pdf` is committed so
  the current draft is readable without a TeX install.

## Framing gates (decided 2026-08-21)

The paper's stance is: a rigorous head-to-head across model families and three
real EHR systems, failure modes reported honestly. Landmark ("could transform
AI for healthcare") framing is deliberately deferred until all three gates are
met with measurements, not adjectives:

1. Blind external or temporal validation on GEMINI with the pipeline unchanged.
2. A win on a recognized external benchmark protocol (MEDS-DEV / EHRSHOT).
3. Clinician-in-the-loop evidence that the interpretability changes decisions
   (Phase 2, retrospective).

The physician-preference IV study (provider variation as instrument on GEMINI)
is tabled as its own future paper; its best use here is external validation of
the concept lever once the lever passes its internal test. Provider identity is
preserved in the GEMINI extraction so the option stays open.
